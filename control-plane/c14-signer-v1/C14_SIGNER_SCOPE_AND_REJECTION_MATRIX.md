# C14 Signer v1: scope and rejection matrix

This Draft service only signs a canonical C14 receipt. It does not determine
the verdict, dispatch a Runner, execute C14/C13, access a repository, deploy,
or connect to Hong Kong, Production, payment, OTA, providers, or secrets.

## Required request

Exactly four fields are accepted: lowercase `candidate_sha`, `application_tree`,
`evidence_manifest_sha256` (40–64 hexadecimal characters), and `verdict`
(`PASS` or `FAIL`). `issuer`, `gate`, timestamp and receipt ID are generated by
the service. The KMS version resource and issuer are configuration, never
request input.

## Fail-closed rejection matrix

| Condition | Result |
|---|---|
| Any additional/missing field | `REQUEST_FIELDS_MISMATCH` |
| Deployment, Hong Kong, production, payment, OTA/provider, secret, runner or dispatch field anywhere in JSON | `FORBIDDEN_CONTROL_PLANE_FIELD` |
| Invalid digest, verdict, issuer, UTC clock or KMS version resource | reject before signing |
| Missing KMS configuration, KMS failure or empty signature | no receipt returned |
| Non-POST endpoint, non-JSON, invalid body length | HTTP reject |

Cloud Run IAM must enforce the caller identity. This source package does not
accept caller identity, key material, endpoints, callbacks or command fields
from requests.
