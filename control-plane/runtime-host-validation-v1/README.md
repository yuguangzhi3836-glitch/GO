## 验收矩阵

| 项目 | 目标主机实测 | 必须读回的证据／通过条件 |
| --- | --- | --- |
| 身份与包 | 在执行前核验宿主身份、系统版本、Python/systemd、源码和 unit 字节 | 实例身份绑定、版本、完整包清单及摘要与候选一致；环境不符即停止 |
| 安装前快照 | 记录服务/账号/目录是否存在；记录原状态，不覆盖未知内容 | 不存在证明或旧状态备份；专用本地磁盘，非 NFS/共享卷 |
| 权限 | 从实际服务进程确认 UID/GID、capabilities、NoNewPrivileges、umask；受控写入拒绝探针 | 非 root、capabilities 空；代码不可写，状态目录0700；无宿主凭据及 Docker socket |
| 隔离 | 读取实际进程 namespace；执行仅隔离实验网络的拒绝探针 | 私有网络与宿主不同，无外部路由/监听；不连接真实供应商或业务端点 |
| 资源 | 读实际 cgroup 配置，并以独立受限夹具验证内存/任务限额和 CPU 节流 | 256MiB、32 Tasks、50% 单核预算有效；记录 memory.events/pids.events/cpu.stat；不以配置文本代替执行证据 |
| 探针闭环 | 预置有固定测试标识的 RUNTIME_PROBE，启动原样候选服务 | 领取、完成、Evidence 链完整；业务/审核任务保持未领取 |
| 服务停止 | 正常停止并观察进程、健康文件、任务库 | 不再领取、进程退出、状态保留；不影响其他服务 |
| 故障重启 | 对本专用服务做受控进程终止并观察 systemd 恢复 | PID/run_id 更新、旧健康记录过期不当健康、有效租约不抢占、过期任务恢复 |
| fencing | 在同一隔离状态库制造旧 attempt 与新 attempt 接管 | 旧执行的 complete/renew 被拒；新持有者结果保留，Evidence 无重复完成 |
| 重启限制 | 受控失败夹具，限制破坏面为该服务 | 60秒内超过5次不无限重启；失败记录可读，恢复操作有证据 |
| 开机恢复 | 完成前序后，经绑定授权重启专用 VM | boot_id 变化、启用关系、开机自动启动、状态/租约/Evidence 恢复；服务重启不可冒充主机重启 |
| 断电恢复 | 仅在具有外部救援入口的专用 VM，绑定授权后受控硬重置 | 独立记录；检查 SQLite integrity_check/Evidence 和任务恢复；不能执行则 NOT_RUN，禁止用正常重启代替 |
| 备份恢复 | SQLite backup API 生成副本，停止服务后仅在隔离副本恢复 | integrity_check=ok，长期状态和任务一致，Evidence 链有效，不删除原库 |
| 安全回退 | 停止专用服务、保留 DB/WAL/SHM/日志 | 最终 STOPPED/HOLD；禁止回退到不具 fencing 的旧执行器处理未完成任务 |
| 边界与结案 | 比对计划前后宿主状态、任务及产物 | 无保护组件变更、无真实外部 effect；证据齐全且独立复核才登记 PROVEN |

## 首次 E2E 的控制顺序

1. 补全主机实例/环境、正式入口和已安装能力的只读证据；冻结可执行验证夹具与计划。
2. 独立审核者对上述宿主绑定的拓扑计划出具明确结论。作者不能自行填写通过。
3. 将本轮用户推进意图绑定为该宿主上的明确安装、故障注入、VM 重启/硬重置及首次 E2E 授权；
   保留实际授权来源和范围，不能从本文件导出授权。
4. 通过已批准的首次验证入口执行。首次验证许可与最终常驻许可分开，不能先把“已证明”布尔值设 true 来启动。
5. 执行矩阵，逐项输出真实结果；任何未知、摘要不符、越界或超限，立即安全停止并保留证据。
6. 控制面验签并读回 Evidence；独立复核结果与候选/宿主/计划完全匹配，才登记已证明拓扑。
7. 本轮默认停止在 STOPPED/HOLD。持续常驻、真实 AI Worker、外网、凭据及 PG 协调集成属于后续独立范围。
