## 3. 资源预算与容量结论

RESOURCE_BUDGET.json 记录镜像/压缩包实际字节数，预算采用：

`2 × 压缩镜像包 + 2 × 解压镜像层 + 512 MiB 数据/日志/备份 + 2 GiB 宿主机保留空间`。

双倍项覆盖下载/合并副本及 Docker 导入暂存；这是保守规划，不是 Docker 的实测峰值。
内存预算为 768 MiB 容器上限加 768 MiB 现网缓冲；CPU限制只是隔离单会话预算，不是吞吐承诺。
CI_RESOURCE_SAMPLE.json 是 CI 单次采样，不是香港负载或峰值证据。

用户转交的香港预检：2026-09-11 09:45–09:46 CST，可用磁盘 5,705,682,944 B，
可用内存 1,822,203,904 B，2 logical CPU，Ubuntu 22.04.5 / x86_64 / Docker 29.7.2 / Compose v5.5.0。
这些是回执陈述，未附可独立核验的原始命令输出，且绑定 DEPTH37R2 预检，不代表当前容量。
容量门禁保持 HOLD_FRESH_PREFLIGHT_AND_BUDGET_APPROVAL：批准前必须只读复核当前资源、现网负载和端口。
不得删除现有镜像、日志、媒体或酒店数据，不在此节点构建镜像；不足时提出资源方案，不自行扩容或清理。

## 5. 停止与回退方案

这是新增独立环境的撤回，不覆盖现网，因此没有把 R3.1.5 切回旧镜像的动作。
执行前记录现有 Compose/容器/镜像/配置哈希、候选哈希、授权 ID、目标资源清单及容量快照；记录失败则拒绝变更。
若首启健康失败、资源越限、任何现网漂移或隔离边界异常，在批准包含停止权限时只停止本次新容器，保存日志、镜像及测试卷。
不自动回滚、不执行 down -v、不清理全局镜像/网络、不删除测试卷、不恢复旧现网值。
停止权限未批准时回报 HOLD，不自行追加操作。
原始验收 runtime 拒绝重用已有 session；再次启动需要新审批的 session/卷与独立记录，不能删库假装恢复。
需要重启持久会话或全工作器运行时，应由指挥中心另出候选并验收，不能让香港临场补代码。
数据导出只限合成验收数据；账户密码、cookie和token必须私下交接，禁止入仓库、CI产物或讨论区。
