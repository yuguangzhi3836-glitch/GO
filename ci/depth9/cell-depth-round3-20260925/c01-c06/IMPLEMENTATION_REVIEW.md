# C05 isolated cancellation policy operations candidate

Baseline: PR246 ecab110746760ac46acec60f0c96545e02b90a66. Product scope and six local source/test hashes are in FROZEN_FILES.json. Root owns shared API registration, navigation and browser integration. This report is developer evidence, not independent acceptance or deployment authority.

The new admin workspace supports readable version diagnostics, draft terms, comparison against the current version, explicit confirmation, separate-maker/checker activation, and revocation. Permissions are derived from current persisted identities and sessions, with authoritative UI capabilities. Read-only users cannot draft or mutate; makers cannot activate their own versions. Neither policy hashes nor approval strings are user-entered authority.

Existing CommercialPolicyVersionRow and CommercialAuditEventRow tables are reused, without a migration. Dedicated C05 transitions do not use generic commercial approval methods. They require authenticated permissions, canonical scope/content binding and a per-offer audit sequence. PostgreSQL advisory transaction locks serialize version allocation, activation, revocation and booking acceptance; SQLite mutations use BEGIN IMMEDIATE. Activation supersedes the previous current version atomically. Superseded/revoked versions cannot be reactivated, and an older draft cannot replace a newer non-draft version. This is an application-controlled audit chain, not a claim of cryptographic protection against arbitrary database administrators.

Consumption is opt-in through GO_RIDE_ISOLATED_POLICY_REGISTRY=1 and allowed only in local/test/demo environments. When enabled, no file-fixture fallback is allowed: missing, expired, unverified, tampered or revoked registry policies HOLD new bookings. The prior opt-in fixture-file mode remains the default engineering path unless the registry is explicitly enabled. No real commercial policy verifier has been introduced: real_policy_state remains HOLD_UNVERIFIED. Ordinary expiry/revocation of an approver login session does not retroactively withdraw an already accepted policy; later governance mutations still require a live authorized session.

Booking validates the current registry policy under the same offer lock through snapshot commit, so revocation between quote and booking rejects the new booking. Existing accepted snapshots remain immutable and refund terms continue to use them, with existing payment/refund authority gates unchanged. This feature does not contact suppliers, execute money, or change fees on historical orders.

Widget behavior: asynchronous duplicate submissions are blocked, each new state clears confirmation, version conflicts require reading and explicitly confirming the new version, and unknown mutation responses are not presented as success. A failed read removes actionable controls; detached navigation cannot submit. Text is escaped. The workspace integrates through GORidePolicyOperations.render({container,request}); request accepts an object body, and root's console adapter serializes it.

Validation: policy-operations-final.xml reports 79 passed, 0 failed/error/skipped across the new operations tests, accepted-policy tests, existing mobility refund consent and ride synchronization tests. widget-tests.log reports 7 passed covering confirmation, duplicate pending actions, revision conflict, network unknown, server capabilities, XSS and navigation detach. Full PostgreSQL increment and real browser role workflows are assigned to root/C12 and are not claimed by these local results. C13/C14 have received the frozen manifest for independent review.
