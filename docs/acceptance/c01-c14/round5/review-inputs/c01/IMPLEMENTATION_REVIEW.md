# R5 C01 content approval permission repair

Baseline cba99d085ffe8ff576e44120ac796e59b4ff11bf. This increment repairs content approval authorization and gate readback only. It does not implement occupancy, establish real hotel authority, certify media rights, or make publication/page/booking consume approved snapshots.

The existing route authenticated GO_ADMIN but did not require approval permission, while the service trusted a caller role string. The route now checks admin:approve before object lookup; the service independently checks the persisted active GO_ADMIN, current permissions and active DB session. Snapshot creation likewise requires current admin:rules. A caller-provided Principal or role string cannot replace persisted checks.

The exact-hotel/actor ACTIVE reserved HOTEL_CONTENT_APPROVER binding is read from HostedStaffRoleRow. The existing public assign_role enumeration cannot grant this reserved role. This batch creates no grant endpoint or global administrator self-grant. Binding consumption is allowed only with explicit GO_HOSTED_CONTENT_AUTHORITY_MODE=ISOLATED_FIXTURE in local/test/demo and the fixed server-held isolated fixture marker. Test setup explicitly provisions test rows; no autouse authority, real hotel consent or new authorization architecture is introduced. Real first authorization remains HOLD_UNVERIFIED.

A v2 snapshot envelope contains schema, hosted_hotel_id, version, created_by and payload, bound by the complete content hash. Original hotel contact fields remain inside payload; no authority fields are inserted into the hotel's real contact_json. Old snapshots remain present and are not automatically upgraded. Approval rejects the maker, obsolete snapshots, changed hotel source payload or mismatched hash.

The approval evidence_reference column stores a typed JSON envelope binding the exact role row ID and full field digest, snapshot hash and the user's original reference. Its total length is checked before writing against the existing 512-character column. API readback returns the original reference plus separate approval_metadata. Gate validation recalculates the binding and snapshot hashes, so a replacement role row or rehashed changed content cannot revive an earlier approval. Revoked role, inactive user or removed approval permission prevents future approval consumption. Normal expiry of an old approver login session does not retroactively revoke a valid approval; any new mutation still needs a current session.

Latest decision is authoritative, with monotonic decision timestamps under the hotel transaction lock. REJECT blocks an older APPROVE. Changing a decision requires the current expected_decision_id; a delayed old approve request cannot silently reverse a later rejection. Exact current-decision replay is idempotent. Snapshot version creation and approve transitions lock the hotel before reading/updating current state; SQLite uses BEGIN IMMEDIATE and PostgreSQL uses the row lock. No migration is needed.

Malformed decision/hash values reject without writing instead of raising TypeError. Tests retain the old five media/version assertions with explicit isolated authenticated identities and scoped bindings. New cases cover real readonly HTTP denial, service permission/session rechecks, wrong-hotel/unbound/self approval, forbidden public role assignment, nonisolated environments, latest reject, immutable source/binding substitution, legacy weak records, reference bounds and concurrent version/approval writes. Test results and hashes are stored alongside this report; independent C13/C14 and unified PostgreSQL/CI remain separate gates.

The inherited media function and publisher/page consumers remain explicit unresolved boundaries. OPERATIONS_ACCEPTED in this pilot gate can only reflect the limited isolated checks reported together with real_hotel_authority_state=HOLD_UNVERIFIED; it must not be treated as real supplier approval, copyright verification or deployment authorization. Frozen acceptance definitions and all previous evidence are unchanged.
