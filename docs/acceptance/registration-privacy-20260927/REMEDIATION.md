## 源码可证实的数据流和基础

用户浏览器 → GO API → 数据库：注册邮箱/密码用于账号合同与安全验证；密码经现有密码散列服务处理，明文不写库。消费者显示名/手机号为选填资料，供应商企业/酒店、联系人、地址用于该用户请求的合作入驻。上述必要性及告知文字须逐字段由正式条款审核确认；未证实者不自动认定“合同必需”。

GO API → 现有 SMTP → 收件邮箱：发送地址在 registration_email.py 固定为 postmaster@goaidirect.com；配置引用 hk-staging-registration-email，密码来自既有只读文件。2026-09-19 用户提供的交接说明称真实发信已收到；这是既有发信可用性线索，不能推导供应商数据处理合同、存储地区或留存期限已通过审核。本轮不重复发送真实邮件。

已提交的默认法律库仍为 DRAFT，企业名称和隐私邮箱有既有记录；注册地址、统一社会信用代码不在这个默认草稿中。sync_registration_profile.py 应继续从已有受控资料同步，禁止重新编造。本轮没有取得其完整现场源数据，也没有覆盖已存在配置。

## 受理流程

1. 用户登录 C/B 对应账号，从隐私页面提交类型；仅由会话解析本人身份，不接收客户端 user_id；可看申请状态和注册确认记录。
2. GO_TRUST/GO_GOVERNANCE 经现有身份和权限通道读取 /internal/privacy/requests，先转 IN_REVIEW，再核实范围、请求人及必要资料。不得索取密码/验证码。
3. 资料访问、更正、删除、注销、转移、限制处理跨表/供应商执行须留下受控凭证；受限保留填写法律依据、限制范围及复核日。此 API 是处置记录，不自动执行或证明删除。
4. 有证据才可登记完成；拒绝须依据和说明。用户可见结果和理由，逾期由 worker 报警。旅行信息库授权可直接撤回；注册协议接受是合同记录，不伪装为可撤回的营销同意。

## 运行准入和恢复步骤（描述性要求，不是执行授权）

新增 registration_privacy_evidence_path 指向由运营挂载的只读 JSON，不含密钥。schema_version=1，status=APPROVED，terms_version 必须等于被批准正文版本，valid_until 为未到期的带时区时间。operator、data_inventory、smtp_processor、cross_border、retention_schedule、backups、rights_operations 每项必须含 reviewer、reviewed_at、evidence_ref、sha256、scope。缺项、过期或条款不匹配拒绝准入；这些结构检查不验证材料真实性，不替代人工审核。

恢复期间先关闭 registration_verification_enabled、隔离外发；执行获准迁移/恢复；使旧运营证据失效，启动 worker 作废挑战并清理过期记录；从备份外受控删除清单重放人工删除/限制记录；核查备份及供应商处置、心跳/告警、权限和邮箱配置后才能重新批准证据并开放。API 可以有多个实例，恢复顺序不能依赖恰好先收到用户请求。

仍使用既有 reconciliation 服务，无新增服务角色；迁移新增三张表，0133 等运行数据库状态未被本轮修改。提交不会修改在线配置、法律审批、外部供应商或部署状态。
