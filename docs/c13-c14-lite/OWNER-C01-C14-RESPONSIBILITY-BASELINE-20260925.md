# GO 指挥、调度及 C01–C14 团队职责统一说明

日期：2026-09-25

> 本文件记录 Owner 于 2026-09-25 补充确认的 C01–C14 统一组织职责。它是 #247 后续 C13/C14 Lite 角色设计的职责基线，不构成任何具体版本的部署指令。

## 一、组织架构与责任原则

真人负责人 → GO指挥中心 → 调度中心 → C01–C14 AI团队。

C01–C14是GO的常设团队，持续承担系统建设、业务运营、平台运维、质量验收及规则治理。职责覆盖开发、上线、日常运营、异常处理和持续改进，不随部署完成而结束。

- **指挥中心**：接收真人目标与授权，确定优先级和执行边界，汇总运营、质量与风险情况，控制部署授权。
- **调度中心**：拆分派发任务，管理依赖、执行状态、超时恢复与跨团队协作，跟踪问题直至闭环。
- **C01–C14**：按固定领域承担长期责任，提交成果、运营结果与审核证据。
- **香港执行器**：执行正式派发的现场任务。香港是运行环境，不改变C01–C14的责任归属。

## 三、运营责任不转移

部署完成后，各团队继续负责本领域运营，不能将所有运营问题统一甩给香港或C12。

例如：

- 酒店库存错误由C01负责；
- 机票退改异常由C02负责；
- 租车争议由C04负责，涉及资金处理与C11协作；
- 支付、退款、对账异常由C11负责；
- 服务器、网络、数据库基础设施故障由C12负责；
- 修复效果由C13按范围独立复验；
- 法律、合同及规则争议由C14审查。

跨团队事件由调度中心确定主责团队与协作团队，跟踪至闭环。各团队不得越权改写其他领域的权威事实。

日常运营在既定授权范围内执行；部署由真人通过指挥中心下达指令。

## 四、开发、审核与部署边界

- 各业务团队负责本领域规则与功能实现。
- C14负责宪法、权限、法律、监管和合同审查；相关问题必须闭合。
- C12提供权限和规则的技术执行机制。
- C13负责独立质量验收，不承担被验收功能的开发，不用开发者自测代替独立验收。
- C13、C14输出独立审核意见，注明候选版本、范围、证据和结论；不冒充真人签字或部署授权。

## 五、香港检查与部署流程

1. 业务团队完成开发、自测及相关C14审查整改。
2. C13对固定候选完成独立质量验收。
3. 指挥中心形成部署方案；调度中心派香港执行器进行部署前检查，C12负责执行能力，C13负责验收标准与必要的异常复核。
4. 检查通过后，真人在指挥中心对明确版本、环境及范围下达部署指令。
5. 香港执行器按授权执行，完成部署后健康检查和关键业务验证，回传证据。
6. 系统进入持续运营，各领域仍由对应C01–C14团队负责。

香港部署前检查覆盖版本一致性、环境配置、资源与依赖、数据库迁移条件、备份恢复及停止条件，不重复整套C13业务验收。发现影响原结论的差异时，补验受影响范围。

部署失败时，按获批方案停止、回滚或恢复；未取得成功证据，不得报告部署成功。

## 六、香港同步要求

请按以上分工核对现有配置、任务归属和运营责任，回传一致项、冲突项及待修正项。

保留已有有效成果和证据，按版本与范围核对适用性。明确区分“职责已登记、任务已派发、正在执行、结果已验证”，不得将团队配置存在等同于团队正在运行。
