# GO 注册、隐私、用户同意、邮件及数据保留审核规则

核查日期：2026-09-27。性质：C14 实质审核依据与 GO 内部工程控制；不替代监管机关认定或个案法律意见。

## 1. 生效与适用边界

本文件在分支中是治理提案；经负责人的明确授权、PR 审核合并进入 main 后，才作为仓库声明的 C14 规则来源。法律自身的效力不取决于本 PR。不得把合并规则等同于批准注册条款、确认企业资料、开放注册、产品验收或部署授权。

覆盖 C/B 端注册、企业资料同步、隐私告知、同意记录、邮箱验证、邮件发送及有关数据生命周期。审核首先列明经营主体、服务对象所在地、处理地点、数据类别、目的、处理者/受托者/接收方角色及跨境路径。中国内地规则按其适用范围判断；香港规则须结合实际经营和处理活动判断，不能仅凭服务器地区排除内地义务，也不能仅凭香港服务器就认定所有香港规则自动适用。其他业务、地区和特殊人群触发的规则另行补充，不把本清单宣称为全部法律。

以下 L 编号标识法律/官方说明来源； G 编号是 GO 采用的工程要求，并非法律规定了某个算法、分钟数、审批字段或 UI 控件。

## 3. 法律要求与审核问题

### 注册、身份资料与合同

- **L1/L2：** 对每个个人信息字段说明合法基础、必要性与用途；不得把所有处理一概归为同意，也不得用“合同所必需”覆盖营销等非必要目的。注册前告知处理者名称、有效联系方式、目的、方式、种类、期限或确定方法，以及权利行使途径。
- **L3：** 注册协议应可阅读；免责、责任限制等重大利害关系条款须合理提示并可说明，不合理排除主要权利等条款不能因用户勾选而当然有效。审核需查看实际文本与移动端呈现，不能只检查版本号。
- **G-REG：** 沿用现有受控企业资料源。注册地址、统一社会信用代码、邮箱及主体名称同步须有来源、权限、变更记录和一致性核验；缺失或冲突明确阻塞，禁止编造、静默覆盖。格式/校验码验证不是工商身份或代理权限核验；邮箱验证也不是实名、年龄、员工或业主资格认证。
- **G-OPEN：** 正式注册就绪条件必须同时成立：已批准且有效的协议/隐私版本、有效主体资料、可用且安全的验证配置及本范围必需的合规条件。服务端重新判断，不能仅前端判断，也不能用 OR 将单个条件满足视为全部满足。DRAFT 文本、配置存在或模拟发信成功均不得独立打开正式注册。自动开放只可响应已获批准的有效配置；不得由程序自批条款。

### 隐私与用户同意

- **L1/L2：** 基于同意的处理须知情、自愿、明确；目的/方式/种类改变依法重新取得同意；提供便捷撤回，不能以拒绝非必要处理为由拒绝基本服务。敏感信息、向其他处理者提供、出境等按适用法律分别核查单独同意及例外，不用一个总勾选替代。
- **L1/L2：** 涉及不满十四周岁个人信息时落实监护人同意及专门规则；敏感信息满足必要性、保护措施、特别告知与适用评估要求。不得为证明成年而默认额外收集身份证。
- **L1/L2：** 实际提供查阅、复制、更正、删除、撤回、注销及适用的转移/限制处理渠道，合理验证请求人，避免向他人泄露；不能只有隐私文案而没有受理程序。法定保留情形与删除请求分别处理。
- **G-CONSENT：** 合同接受、隐私告知、基于同意的处理、可选营销用途分别表达和记录；必需同意不得预勾选或以沉默代替。服务端验证用户接受的有效版本，保留最少必要的主体关联、目的、文本版本/摘要、时间和明确动作，支持撤回及版本追溯；不以过量设备指纹或验证码原文作“证据”。
- **G-RIGHTS：** 证据包含真实可用的联系/受理入口与职责，不把占位邮箱、失效链接或界面显示“已注销”当作请求已完成。

### 邮件与验证

- **L4：** 禁止伪造发送者、利用非法取得地址或未经授权系统发送邮件。商业广告邮件须事先获得明确同意、按规定标示广告并提供有效拒收渠道，拒收后停止；不得将用户请求的验证码邮件自动视作营销许可。第14条拒收联系方式有效期要求按其适用情形核查。
- **L1/L2：** SMTP 供应商涉及委托或其他接收方时，应识别角色、约定目的范围和保护义务、监督履行，并处理必要告知、同意及评估；“已有 SMTP”不等于这些义务已有证据。
- **G-MAIL：** 事务验证与营销分开，不在验证码中混入推广来规避营销要求。使用真实授权发件身份及加密传输，凭据限权管理，日志不记录验证码、令牌或 SMTP 密码。
- **G-VERIFY：** 验证挑战须不可预测、限时、限次、限频、绑定邮箱与用途；数据库只保存安全验证材料（如密钥隔离的 HMAC），并原子消费、防并发复用和重放。不得把发送失败标记为验证成功；明确失败/重试响应，防账户枚举与邮件轰炸。HMAC/TTL 是 GO 工程选择，并非法定指定算法或法定分钟数。

### 数据保留与删除

- **L1 第19、47条 / L2 第21、24条：** 各类数据按必要的最短期间或适用法定期限保留；公开期限或确定方法及到期处理。目的完成、期限届满等删除条件到达时处理；依法须保留或技术上难以删除的，按适用规则限制后续处理，不能继续营销。
- **L1 第55–56条：** 触发个人信息保护影响评估的活动先评估；评估报告和处理情况记录至少保存三年。**L2 第12条**向其他处理者提供/委托处理个人信息和重要数据的处理情况记录至少保存三年。这些是特定记录要求，不是把验证码、所有邮箱数据统一存三年。
- **L4 第10条：** 电子邮件服务提供者的相关发送/接收记录保存60日，先判断 GO 是否属于该义务主体；不得据此把所有注册挑战强制保存60日。
- **G-RETENTION：** 必须有按数据类别的保留表：字段/存储位置、目的及依据、起算事件、期限或可执行确定方法、责任方、删除/匿名化/受限保留措施及验证方式。至少覆盖未完成注册资料、有效/失效/已消费验证码材料、账户及企业联系人、同意与条款记录、发信日志、反滥用记录、审计记录、备份及供应商副本。没有统一默认“永久”期限；数值须说明依据，不能把测试 TTL 当法律期限。
- **G-CLEANUP：** 验证码“到期不可用”与数据“到期删除”分别验证；只在下次请求时清理无法证明无后续请求时的删除时限。须证明定时/有界清理与失败监控、备份到期处置以及恢复后重放删除要求；保留合法审计证据时最小化并限制用途，避免销号后重新激活数据。清理不要求新增服务角色，可复用获准机制。

### 香港、出境与安全

- **L1/L5：** 列出注册页面、API/数据库、日志、备份、SMTP 与运维访问的所在地及数据流。涉及出境时按实际主体、数量、类别及用途评估适用机制；必要跨境订房等豁免不能自动扩展到所有注册或营销数据，也不当然免除告知、单独同意、影响评估等仍适用义务。
- **L6（适用时）：** 核查公平适量收集、准确性与必要保留、用途限制、安全、政策透明、查阅更正及受托处理保障。新用途及直接促销另核合法同意/退出；沉默不等于直接促销同意。需区分监管机关说明与法例原文，争议以正式法例及适用性审查为准。
- **L1/L2、G-SECURITY：** 结合处理风险核查权限隔离、传输/存储保护、凭据管理、漏洞与事件响应、受托方监督及适用审计/影响评估。测试证据脱敏，禁止把真实用户、凭据、生产邮件内容上传审核附件。

## 4. 证据、结论和开放条件

审核材料必须绑定候选提交及应用树；逐项列出规则定位、适用性、实现位置、测试/业务文件证据和缺口。允许有依据的“不适用”，不允许无理由跳过。

| 范围 | 最低证据 |
| --- | --- |
| 注册就绪 | 条件组合测试，直接 API 绕过测试，资料来源与权限，协议批准/版本证据，手机端可读性 |
| 同意及权利 | 文本与动作追溯，拒绝非必要同意、撤回、更正/删除/注销流程；旧版本/伪造同意负例 |
| 验证/邮件 | 过期、错误次数、用途/邮箱错配、重放、并发、发送失败、权限与日志脱敏测试；配置引用及供应商角色 |
| 保留 | 分类型保留表、有界清理与失败处理、无后续请求的清理证明、备份与受托方处理安排 |
| 适用性与跨境 | 主体与数据流清单、法律基础、适用机制/豁免依据、所需同意/评估/合同证据 |

证据已经显示违反要求时提出明确不符合项；缺少决定性资料、适用性未明或无法读到证据时记为阻塞，不得默认合规。正式输出继续使用现有 C14 契约允许的 verdict，本文不新增机器状态或更改门禁。源码范围的结论不能代表运行环境已经满足条件；影响本次候选范围的未解事项不得藏在“上线后补齐”中后给出无条件通过。

隔离测试可使用合成资料和受控邮件替身，其结果不能充当真实发信、主体真实性、条款批准、出境合规或物理手机复验证据。C14 流程执行成功不等于 C14 PASS；规则补齐后重新审核，不能沿用旧结论或自行签发通过。C14 通过后才继续既定 C13 与获准发布流程。

维护时通过独立治理 PR 记录来源、条文、适用范围及变更原因。法规更新、业务地区/数据流变化或新的实质规则缺口触发复核。规则审核与产品验收分别留痕，负责人的规则合并批准不是对候选法律合规的背书。
