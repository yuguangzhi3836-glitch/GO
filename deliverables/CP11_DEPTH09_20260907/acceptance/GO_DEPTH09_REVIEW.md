# GO DEPTH09 · 一键建酒店库复核

**结论：功能尚不齐全，真实批量复制尚未验收。两个门禁均为 HOLD。**

用户要求一键建库达到快速、准确、可复制。本批对已封存 DEPTH08 的建库调用链做源码核对，
并在独立副本补齐关键准确性缺口。DEPTH08 原件、自治内核和既有 116 个迁移不改写。

## 实质发现与本批修复

| 问题 | 原实现证据 | 本批结果 |
| --- | --- | --- |
| 同名误合并 | `_match_profile` 在一侧地址缺失时允许只凭名称合并 | 必须有稳定来源身份或足够的地址/位置依据；歧义拒绝；同源并发序列化 |
| 新资料被旧资料覆盖 | 历史快照一起参与合并；SQLite 无时区值的排序受进程时区影响 | 同一来源只使用最新快照参与当前事实合并，时间统一为 UTC；旧快照保留审计 |
| 名称地址即发布 | `_merge` 与手工 PUBLISH 只检查名称和地址 | 官网目录、房型事实、来源绑定、实际媒体及目录复核共同决定可发布状态 |
| 官网只采基本信息 | 通用解析器没有提取房型目录 | 新增有界、多页、显式 Hotel—HotelRoom/Suite 关系采集；不猜测页面标题或任意图片归属 |
| 草稿/待补资料计入完成 | 区域任务统计按“已处理数量”推导完成，DRAFT 也计页面 | 单店质量未过则 NEEDS_ENRICHMENT；仅通过并实际发布的页面计入批次页数 |
| 错误更新影响已发布页 | 缺乏基于质量的新旧版本切换 | 不完整新候选留在草稿，继续提供上一完整版本；人工下架状态保持 |
| 图片计数掩盖错绑 | 总图片数不能证明各房型对应照片可读取 | 逐房型核对来源 URL、缓存字节、哈希与当前发布状态；无关图片不进入公共页面 |
| 管理只读身份可写 | 旧写接口只判断 GO_ADMIN 身份 | 所有相关管理写操作再检查 `admin:rules` |

## 不能写成“已经完工”的边界

| 能力 | 当前结论 |
| --- | --- |
| 酒店 URL / 来源种子登记 | 已有入口；新采集器已接入官方来源分支 |
| 截图 → OCR → 唯一酒店确认 → 建库 | 当前建库调用链中未找到完整接线，不计为完成 |
| 官网全房型采集 | 支持明确结构化关系的一类站点；JS 页面、其他集团/独立酒店模板仍需适配 |
| 官网房型总数核验 | 不能把结构化条目数或物理客房数量当作完整房型总数；需独立官方目录证据 |
| 官方图片自动下载与入库 | 当前 Discovery 仍只保存候选 URL，与 MediaHarvester 是分离入口；全自动编排未完成 |
| 媒体并发元数据可靠性 | 本地 JSON 索引的跨进程更新一致性仍待处理；不能据此启用高并发全国建库 |
| 区域任务中断恢复 | 现有 Redis `BRPOP` 出队后无确认恢复协议；DEPTH08 通用持久执行底座尚未替换该链 |
| 标准档案 → 官方直订房型池 | 敖麓谷雅有单店配置器；跨酒店通用、完整、原子投影未验收 |
| 三端真实体验与香港运行 | 本次未部署、未完成真实浏览器/真机与香港现场验收 |
| 真实复制速度与准确率 | 只有隔离合成场景证据，没有真实跨酒店性能承诺 |

## 验证与证据解释

本批新增 43 项功能测试；早期相关矩阵共 55 项通过。最终完整回归的实测数字以
`verification/current_build/depth09/CURRENT_BUILD_STATUS.json` 和原始 `full_regression.xml` 为准。
`targeted.xml` 从同一次最终完整回归提取新增测试，不将多次运行拼接为全量通过。

功能测试使用真实 SQL 事务、6 线程竞争、实际 PNG 编解码与磁盘哈希检查，以及应用认证 API。
10 家合成酒店各有独立官方房型关系和 7 张合成图片，逐家生成页面并重复导入，
核对酒店/房型/媒体不串店、档案/快照/页面版本不增生。该场景不能替代真实官网抓取或浏览器验收。

新测试发现的时区问题已在实现中修正，没有通过改变测试机时区掩盖问题。
新增发布条件还需要现场存量页适配：无新质量证据的旧公开版本会被阻断；须在香港部署前盘点。
无数据删除、无真实酒店迁移、无任务下发、无邮件、无订单或资金动作。

## 当前官网与应用采集器的区别

2026-09-07 通过网页读取核对，凯悦敖麓谷雅官网仍显示 17 项房型；部分房型只有两张官方图片。
因此新规则按官网真实图片逐项对应，避免为凑数量借用其他房型图片。
参考：[敖麓谷雅官方房型页](https://www.hyatt.com/unbound-collection/zh-CN/hrbub-aoluguya/rooms)。

应用自身的只读采集探测在当前执行环境返回 `DISCOVERY_SOURCE_DNS_UNRESOLVABLE`，
已单独记入 `live_official_probe.json`。网页可读取不能替代应用采集器已跑通，也不能证明香港可抓取。

实现参考：[Schema.org HotelRoom](https://schema.org/HotelRoom)、
[PostgreSQL 事务级锁](https://www.postgresql.org/docs/current/explicit-locking.html)。

## 快速准确复制的完成口径

应在同一冻结候选下，对至少 10 家真实酒店、多个官网结构执行批次验收，保存每家原始目录和来源快照。
酒店身份无误合并，官方房型清单与关键事实逐项对应，照片不串房型；重复执行不增生，
中途强制终止后可恢复，失败不替换上一完整页面。记录每家总时长、采集请求数、重试次数、
遗漏项与人工处理次数，再确定可承诺的速度。不能用“按钮存在”“HTTP 200”或合成测试通过替代。
