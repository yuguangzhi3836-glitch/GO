# GO DEPTH23 审阅记录

**仍为 HOLD，未全面完工，未部署。** 本累计候选从 GitHub DEPTH21 `ba758eb` 推进，包含 DEPTH22 与 DEPTH23 两批工程变更。

## 本轮实际关闭

- 铁路改签先冻结供应商决定、原报价、旅客票号、证据、补款、原行程，再执行扣款或释放授权。相反回报、不同票号/证据被拒绝；数据库租约、旧执行者隔离、原授权归属/金额/币种核验及同事务完成保护中断恢复。
- 原改签 quote_id 标识历史重试；已有确认历史时不允许省略，避免旧回报错落下一次改签。旧请求返回历史快照，刷新订单才是当前状态。
- 铁路不同报价按班次/日期/席别共用隔离库存，重叠站点区间也保守共用；门票按产品/日期/场次共用。预报价不占位，订单与名额同时落盘，竞争失败不留下多余订单或扣款。
- 改签先占新名额、保留旧名额；确认释放旧名额，失败释放新名额，未知保持两份。退款核验完成才释放，核销仍计入本场次已售数量。重复请求不重复占位或释放。
- 未支付取消核验本人、订单状态与支付意图；一旦支付启动则保持名额待核对。取消先完成时，后续支付根创建拒绝。客户入口先确认，响应丢失也刷新原订单。
- 旧订单没有分配记录时，相关资源保持待核对，禁止从零库存账盲目继续卖。新迁移 0129/0130 不篡改历史；存在确认/占位历史时拒绝删除式降级。
