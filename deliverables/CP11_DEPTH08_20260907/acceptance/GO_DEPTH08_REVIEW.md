# GO DEPTH08 · 14 单元持久执行与恢复

**工程复核候选，FINAL_RELEASE_GATE=HOLD。未部署。**

本轮范围由用户选择：自运营可靠性。继承 DEPTH07 官方酒店账本、个人库、
机票及租车已验证实现，增加自运营持久执行底座与 14 个受控运行观察适配器。

## 已完成的执行链

任务以环境、单元、操作及幂等键绑定唯一身份，同时冻结请求内容、提交人和处理器版本。
重复提交返回原任务；同一身份携带不同内容被拒绝。重启不会重置任务状态或重试预算。

每个本地步骤的业务效果、结果、检查点和执行证据在同一数据库事务中提交。
领取任务产生独立租约令牌与尝试序号。过期或被替换的 Worker 无权写回；
新 Worker 仅从已提交检查点继续。步骤内部异常整体回滚，可重试异常按持久退避时间执行，
达到预算进入 DEAD。取消、暂停/恢复、顺序事件、逐步结果哈希均有持久记录。

每次步骤执行重新核查提交者当前权限、单元暂停状态、C14 权限与法律门禁。
站立自治资格通过数据库保存，保留独立验证证据、到期时间和版本；撤销及到期后不能继续执行。
C13 自我授予自治资格仍被禁止。带未满足条件的法律放行也保持 HOLD。

外部适配器必须有查询原操作结果的接口。发送意图先落盘，出现超时、丢失回执或进程死亡后
转为 UNCERTAIN，恢复 Worker 不重新发送。只有绑定原操作编号的终局证据才能完成核对。
数据库租约本身不能为外部系统提供绝对的一次执行保证，因此本批不声称真实供应商或 PSP 已验收。

## 14 个单元的实际接入范围

以下适配器读取应用数据库中的状态汇总并生成需关注项，每项有两个持久步骤。
不读取原始客户资料、不执行退款或订单变更，不把无异常状态汇总解释为生产放行。

| 单元 | 当前执行内容 |
| --- | --- |
| C01 酒店 | 酒店订单、官方直订、入住后争议状态观察 |
| C02 机票 | 订单与退款状态观察 |
| C03 火车票 | 订单与退款状态观察 |
| C04 租车 | 租车订单、改期报价状态观察 |
| C05 接送/用车 | 用车订单状态观察 |
| C06 景点门票 | 门票订单状态观察 |
| C07 旅行者信息 | 个人资料导入任务状态汇总 |
| C08 GO AI 规划执行 | AI 请求执行状态观察 |
| C09 判断与信任 | 独立推荐决策状态观察 |
| C10 GO Trips | 统一行程状态观察 |
| C11 交易与财务 | 支付意图、财务关账批次状态观察 |
| C12 平台与安全 | 事件投递队列状态及死信观察 |
| C13 独立 QA 与发布 | 已保存的发布验证记录观察，不自行批准发布 |
| C14 宪法与法律控制 | 当前环境任务的 HOLD、失败及不确定状态观察 |

14 项观察属于管理员授权的确定性运行作业。执行底座支持注册经过审查的版本化本地步骤
及外部适配器；本批没有把所有业务能力自动接入新 Worker，也没有为 14 个单元制造生产自治资格。
Worker 持续消费已提交队列；事件触发器与定时任务生产者的进一步接入不计为已完成。

## 验证证据

最终完整回归结果以 `verification/current_build/depth08/CURRENT_BUILD_STATUS.json`
和原始 `full_regression.xml` 为准。`targeted.xml` 从同一完整回归抽取本批测试记录，
不是独立执行后拼接成“完整通过”。

最终完整 Python 回归 1026 项：1020 通过、6 项原隔离 PostgreSQL 检查跳过、0 失败、0 错误，耗时 442.921 秒。本批新增 57 项测试全部通过。

覆盖六线程同键提交/领取、14 单元分别恢复、过期 Worker 拒绝写回、
事务故障回滚、退避与预算耗尽、取消、控制版本冲突、权限撤销、资格撤销/到期、
检查点与请求被改动、C14 越权阻断、条件放行保持 HOLD，以及跨环境访问。

进程故障测试使用真实子进程及强制终止：领取后、事务内部、检查点提交后、
外部模拟效果已发生但本地回执未保存。另有独立 CLI Worker 子进程读取应用队列的测试。
管理 API 验证匿名、供应商、只读管理员被禁止投递，禁止客户端提供任意执行权限，
并验证 14 个观察适配器从应用数据库读取实际汇总且不暴露原始字段。

第一轮完整回归发现一个新测试的配置问题：旧测试文件在收集时改写了进程环境变量，
使 CLI 子进程连接另一份数据库。该测试已改为使用当前 fixture 的真实数据库地址，
之后重新执行完整回归；没有为了修复测试而放宽 Worker 失败行为。
