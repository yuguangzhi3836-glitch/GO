# DEPTH29：原订单重新进入详情与跨端事实读取

用户口径：先完成全系统各模块，部署后产生的真实订单数据后置。隔离库存、价格、支付可用于功能验收并明确标记；酒店房型与内容仍必须有官方来源证据。**本候选未达到全系统 100%，未批准发布、未合并、未部署。**

## 本次实现

- 消费者统一行程包含本人六品类原始订单和本人酒店直订预约，即使尚未付款或未进入行程投影也保留；同一订单不重复显示。
- 网页从行程重新打开原订单，使用固定的详情入口；待付款订单重新读取金额后调用现有确认支付流程，不创建新订单，超时仅刷新原订单，不静默重发支付。
- 旧投影与当前订单时间不一致时，明确标记未知，不将旧确认/付款/退款提升为当前事实；读取不修改投影或账本。
- 原生 App 补充六品类行程入口、租车详情、逐乘机人逐航段的值机与登机牌读取。无证据、过期、重复或不匹配证据保持未核实。航班追踪失败不隐藏原接送订单。
- 原生 HOTEL_DIRECT 详情、待付款及售后完整操作仍未接入；原生品牌组件仍需接入已锁定 V14。网页 V14 资产没有修改。
