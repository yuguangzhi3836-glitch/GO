Base: PR #222, commit `fc521219c53b692df91346669e704f4e6b475df1`.

## Delivered in this slice

New `HOTEL_DIRECT_SUBMISSION_V1` pure validator and 17 independent unittest cases. No database, network, existing service, existing publication predicate or API route was changed. Existing official-replication contracts remain untouched.

Checks: explicit supplier/property/registration/canonical-hotel association references; exact one-to-one confirmed physical-room inventories and mappings; unique asset/usage identities; HERO and each physical room image coverage; declared original SHA-256, image dimensions, bytes and MIME; scoped rights and review references; historical expiry at inventory confirmation; credential key/pattern rejection with non-echoing errors; deterministic sorted JSON SHA-256 with optional expected-hash comparison; detached result with no input mutation.

This contract requires physical-room normalization before submission: combination-sale source entries cannot be assumed to be additional canonical physical rooms. A single original can have different scoped usages; duplicate identical usages are rejected.

All successful results say `STRUCTURE_VALID_EVIDENCE_UNVERIFIED`, `rights_granted=false`, `publishable=false`, `published=false`. References are arbitrary evidence identifiers; no fake HTTPS provenance is created. Credential scanning rejects known credential fields and recognizable credential patterns, but does not claim to recognize arbitrary secrets hidden as opaque IDs.

## Remaining depth / acceptance gaps

This closes only the manifest-format/hash preparatory step, not the full publication workflow. There is no API wiring, administrative approval action or current-state evidence verification in this slice. C01/C12 cannot be rated 100% based on these unit tests.

1. Resolve supplier/property/registration/canonical identity against durable authoritative records, enforce tenant ownership and approved association.
2. Independently verify inventory completeness and room mapping evidence and hotel reviewer authority.
3. Resolve asset IDs and read/hash actual original bytes, compare measured dimensions and tenant/room scope rather than trust declarations.
4. Resolve authorized rights decisions and evidence contents, recheck current expiry and revocation. Historical expiry validation here is deliberately not current rights approval; null expiry alone never grants perpetual rights.
5. Add authorized canonical promotion with immutable reviewed manifest hash, idempotency, crash recovery across application database and media index, and separate approval/publication audit events.
6. Preserve legacy official-replication regressions; test successful publication and public read immediately after revocation/corruption/scope change.
7. Complete real mobile/browser page acceptance, PostgreSQL/concurrency and formal C14 then independent C13 gates.

No live hotel data, rights, inventory, publication or deployment was changed. No broad per-module percentage is justified by this bounded slice.
