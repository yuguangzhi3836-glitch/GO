# 图库重复校验优化 · 2026-09-19

父提交 `a9c36e9cd8a7e7ec0691b876258848bc74cf6331`，继续保存至草稿 PR #226；不合并、不部署、不修改实际酒店。第 7 轮证据为其当时源码的历史结果，本文件记录后续变化。

## 变更

在单次同步读取调用栈内复用原图解码及哈希事实。只保存小型事实，不缓存原图字节、授权、审批、酒店或房型状态。每次复用前检查安全路径、文件设备／inode、大小、纳秒 mtime/ctime 和记录 SHA；文件变化重新读图，解码前后变化拒绝。原图响应仍实际读取并验证哈希。

线程及异步任务身份限定作用域。最外层调用结束（含异常）立即清空并失效，复制 context 也不能在随后请求继续复用。512 项上限只影响性能，不允许跳过校验。

## 本机测量

20 图沿用纯色小图；100 图中 98 张为 1600×900 噪声纹理 JPEG，另 2 张为既有测试原图，总字节约 92 MB。使用隔离 SQLite、同一测量流程，各操作 3 次采样。噪声生成不作为逐字节可复现保证；读取次数比延迟更适合比较。发布写路径未做本轮优化。

|图数|操作|原图读取次数（前→后）|耗时 ms（前→后）|
|---|---|---:|---:|
|20|page|40 → 20|100–105 → 77–79|
|20|image|61 → 21|151–154 → 95–110|
|20|inspection|120 → 20|297–301 → 132–133|
|100|page|200 → 100|2138–2231 → 1167–1171|
|100|image|301 → 101|3195–3253 → 1251–1360|

以上是服务端调用测量，不是浏览器、网络、移动端、并发吞吐或 p95 验收。单图响应仍会检查全图库，因此仍为 O(N)；当前版本没有解决每张图请求重复验证全图库的问题，也不宣称图库性能已全部完成。
